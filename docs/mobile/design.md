# Pods 原生 Linux Mobile 适配设计

日期：2026-11-24。上游及 fork 审查基线：`349be73c8bc2a3340e2b6187df1c0c676b63be82`。工作分支：`feat/linux-mobile-docker`。

本版纠正前一版把移动 UI 审查和修复限于少数共享控件的范围错误。用户原始要求已经包含竖屏、触屏、导航、弹窗与软键盘体验；直接影响这些体验的既有 UI 问题属于本次适配。最小必要改动要求每个补丁有实际失败和移动需求依据，覆盖检查需包含相关页面与交互状态。

原始设计已先于源码开发存档，历史版本见 Git 提交 `abb066f4a4e5ced9edb0d7e0ee4de9c063d5c4a7`。无关业务修复已回撤；用户于2026-11-24单独批准的两行启动修复保持有效。当前纠正轮以 `541159251393f7ddfce55c254495f516239fa525` 为起点，先更新 Google Drive 设计存档，再进行下述 UI 验证与必要修改。

## In Scope

本任务只适配 Linux Mobile / postmarketOS。每个保留的代码块必须对应下表中的需求；实施时继续复用上游 engine / model / view 分层和 libadwaita 组件。

| 需求标识 | 允许的最小改动 | 具体边界 |
| --- | --- | --- |
| M-LOCAL | 手机本机 Docker socket 发现与访问说明 | 保留已有引擎识别和 API 行为；仅选择本地 socket、区分实际访问错误、用可阅读的弹窗说明权限 |
| M-LAYOUT | 366/360 宽竖屏、651 宽横屏及桌面恢复 | 检查相关导航、列表与详情、表单、操作弹窗、搜索和辅助页面；对实测裁切、溢出、不可达操作作局部修复，优先调整现有断点、换行、滚动与 libadwaita 组件属性 |
| M-INPUT | 触屏及软键盘可达性 | 检查点击入口、返回、输入焦点、弹层、滚动和键盘缩短高度后的操作可达性；复用既有 GTK/VTE 输入路径，保留终端辅助键及至少44px的新增触控区域 |
| M-NATIVE | aarch64 musl / Alpine 原生安装 | APKBUILD、实际系统依赖、固定源码校验、已有 desktop/schema/resource 的安装、原生两架构构建；无 Flatpak 依赖 |
| M-LOCALE | 本轮新增控件及原生中文资源集成 | 翻译新增移动控件和权限提示；APK 内映射 zh_CN 到已有 zh_Hans catalog，不改旧文案或补齐整个项目翻译 |
| M-MEMORY | 4 GB 手机的直接资源预算 | 限制客户端 I/O worker 与同时 stats 请求数；归档从整包内存缓冲改为磁盘文件传输，保留原有完成、失败、取消及事件语义 |
| M-VERIFY | 移动体验覆盖与适配改动验证 | 用实际模型和组件覆盖空/非空列表、详情、编辑与完成/错误弹窗、导航、焦点和缩短高度；记录保留原样的通过项和必要修复项，复测桌面、两架构原生安装、本地 socket 与资源改动 |
| M-STARTUP | 用户单独批准的完整启动阻塞修复 | 仅将 images.sort-attribute 的 choice 与 default 从 name 改为 id，共两行；不扩展其他上游修复 |

允许最小修改直接妨碍手机使用的既有 UI，例如双栏展开过早、表单输入行的最小宽度过大、弹窗按钮无法触达、点击搜索后未取得输入焦点。是否修改由源码审查与可复现的实际布局/交互测试决定；页面数量和既有实现身份均不构成排除理由。每项修改记录需求标识、触发场景、修改前证据、最小方案和修改后结果。本轮新增适配造成的回归也须处理。

打包可以声明目标平台实际需要的依赖，例如 GTK 4.22、GLib 2.88、libadwaita 1.9、Rust 1.92 以上，以及 Alpine Docker Top 所需的 procps-ng；不升级上游 Cargo.lock 中的库版本。构建缓存和离线设置尽量放在 APKBUILD，避免扩展上游通用构建框架。

| 明确禁止的内容 | 处理方式 |

| API 版本协商、SDK 补丁、依赖升级、通用最低版本同步 | 不实施；只记录目标平台实际构建要求 |
| 上游发行 workflow、vendor/checksum 修复、通用交叉编译 helper | 恢复上游；原生 APK 使用独立的必要打包路径 |
| 欢迎页旧文案、旧译文、代码风格清理和其他技术债 | 保持原样；只格式化本轮必要修改 |
| 覆盖全项目的业务回归、Registry/search、全量 lint 作为本任务验收门槛 | 从当前补丁和 CI gate 中移除；此前实验作为历史证据保留 |
| Compose、Swarm、独立网络编辑器或额外产品功能 | 不新增 |

超出上述移动 UI 和平台适配范围的上游功能 Bug 若直接阻止适配，先说明阻塞原因、影响范围和最小补丁，取得用户明确批准后再修改。直接相关的移动 UI 修复依据原始需求继续执行。测试保留真实业务路径；不得用测试专用配置、临时包补丁或安装脚本隐藏产品阻塞。

## 运行基线与已有实现

目标来自用户提供的设备规格：Pixel 2 walleye、骁龙 835、4 GB RAM、aarch64 musl、4 KiB 页；postmarketOS / Alpine 3.24；systemd；Plasma Mobile / KWin Wayland，295% 缩放，主要内容尺寸为 366×651 与 651×366，Plasma Keyboard 中文输入。GTK 4.22.4、GLib 2.88.1、libadwaita 1.9.2、Docker 29.9.2 为提供的设备基线，仍需实机核对。

Pods 已有 Docker / Podman 后端、折叠导航、360 宽窗口下限、窄屏底部动作、Adw.Dialog、PreferencesPage、WrapBox 和终端 resize。继续使用 engine / model / view 分层；布局修复优先落在 Blueprint 属性和已有视图回调。保留导航历史、操作名称、请求和业务状态语义；不引入独立手机界面、额外框架或新的后台轮询。共享组件通过后复用其结果，同时检查使用它的页面上下文。

现有证据已经确认 `ClientView` 的668sp双栏展开阈值低于实际最小宽：英文700px、中文695px，右侧按钮在边界截图中被裁切。此问题按 M-LAYOUT 纳入最小修复，候选方案为仅提高该双栏阈值；最终值由侧栏和内容在空、非空、选择及长文本状态下的测量决定，其他页面断点按各自需要保留。环境变量/标签的双输入行、动作完成弹窗按钮行和进程搜索输入焦点作为待复现候选，复现后决定局部调整。

测试使用既有 GObject 模型、真实 GTK/libadwaita 组件及隔离的 Unix HTTP 数据 fixture，覆盖有数据时的页面；通过现有 refresh 入口装载列表，避免增加测试专用产品接口。需要 daemon 的连接检查在已有 QEMU 客体中执行。测试夹具可提供长中英文名称、标签、路径和文本，并触发既有菜单、选择、返回、展开与滚动。

## 已批准的启动阻塞例外

首次完整启动的真实 GTK 测试发现：镜像排序枚举使用 `id`，GSettings schema 却提供并默认使用 `name`，干净配置下发生 GLib-GIO 致命错误。该问题存在于上游基线，影响完整应用启动，也会阻止 Pixel 2 的端到端 UI 验收。

用户在 2026-11-24 明确回复“批准”，授权应用已展示的两行补丁：在 `data/com.github.marhkb.Pods.gschema.xml.in` 中，仅把 `images.sort-attribute` 的一个 choice 和 default 从 `name` 改为 `id`。授权范围不包含其他 schema、迁移代码、枚举或业务逻辑。已有独立实验表明旧 keyfile 中的 name 会按 GSettings 规则回落为 id；批准后需用完整应用启动与既有导航重新验证。具体复现和补丁原文保留在问题清单与 proposals/startup-schema.patch 中。

## 实施顺序与验收

先核对现有 diff 和 UI 覆盖缺口，再将本版设计存档到 Google Drive。按下表建立页面/状态记录，先运行现状，修改确实失败的最小组件，然后复测手机和桌面。测试只断言布局、交互可达性及本次平台改动，保留独立记录中的业务缺陷。最终逐块复查需求关联，更新原生包与证据。

| 验收层 | 本轮检查 | 状态边界 |
| --- | --- | --- |
| 原生构建 | Alpine x86_64 / aarch64 musl、APK 依赖、安装产物和源码校验 | 两架构分别记录，旧宽范围候选的结果不替代当前缩减补丁 |
| 视口与语言 | 360×651、366×651、651×366、366×300、1024×768；导航展开阈值两侧；英文与中文长内容 | 检查实际子控件边界和操作可达性；外框存在或已映射本身不作为通过条件 |
| 导航与列表 | 首页、连接、容器/镜像/卷列表，空/非空、搜索、选择、菜单、详情与返回；宽窄反复切换 | 可见操作无意外裁切，返回栈与已有功能保留，底部动作能触达，桌面恢复既有双栏行为 |
| 详情与辅助页 | 容器/镜像/卷详情，资源、端口/挂载长内容，日志/Inspect/Top/终端及已有动作入口 | 长文本有换行、省略、滚动或展开入口；内容允许按用途滚动，页面工具栏和返回操作可达 |
| 编辑与弹窗 | 连接、创建容器、镜像拉取/构建/标签/推送、卷创建、复制/提交/重命名、清理与动作完成/错误状态 | 查看、编辑、确认、取消可用；字段与按钮不因窄宽被遮住；遵循现有 Adw.Dialog 行为 |
| 输入与缩短高度 | 各类输入行、建议弹层、搜索、长表单与终端；点击后焦点、滚动到字段、关闭弹层及返回 | 在366×300内容区验证几何和焦点；实际Plasma Keyboard协议、中文preedit另在设备上验证 |
| 本地连接 | Docker socket 选择、不存在/文件/未监听/权限拒绝、普通用户组权限 | 不修复其他引擎业务语义 |
| 资源改动 | 同时 stats 请求上限、I/O worker 预算、归档传输内容及有界内存路径 | 不把整项目内存缺陷纳入修复 |
| 完整应用 | 干净配置启动、本机Docker连接与现有管理入口在手机可达 | r1已验证启动和空列表；本轮补充非空状态与操作UI，业务结果不以布局fixture替代真实daemon验证 |
| Pixel 2 | 295% 缩放、触屏、中文 preedit、键盘避让、旋转、Portal、休眠、GPU、RSS/PSS 与功耗 | 需要实机执行，QEMU 结果单独报告 |

QEMU system 已能在沙箱中启动独立的 ARM64 / x86_64 客体内核，并运行 Unix socket、Docker 和 GTK/Wayland。可在模拟机完成的布局、焦点、菜单与导航检查在本轮执行。Pixel 2 图形驱动、触屏命中感受、实际键盘协议和功耗保留为设备验收。r1的已通过记录保留其原覆盖范围；其欢迎页、加载态导航及独立控件结果不作为其他页面的完成记录。

## 空镜像页操作区的补充设计

2026-11-24的固定源码 `182aad8d00fdcf7a4faa73c034cb4ce3f3ef3ffd` 原生构建中，x86_64中英文完整UI用例均通过，但后续逐图审查发现 `empty-images-651x366.png` 中拉取和构建按钮稳定地只剩约1px横线。日志对应 `GtkBox exceeds AdwBreakpointBin height: requested 44/106 px, 1 px available`。现有空态检查只验证页面工具栏与控件横向范围，没有断言这两个按钮在祖先裁切区域中的完整高度；该轮通过结果保留这个覆盖缺口。

问题直接对应 M-LAYOUT / M-INPUT。`src/view/images_panel.blp` 的空态操作区已使用 Adw.StatusPage 内置滚动，但内部 Adw.BreakpointBin 把最小高度声明为1。libadwaita 1.9.2在有断点时不从子控件推导最小尺寸；父容器缩短时，按钮区会降至1px而裁切实际44px按钮。竖排的两个按钮各44px，原间距18px，当前样式需要106px。

最小候选仅把该 `height-request` 从1改为106，保留原336宽度请求、500sp方向切换、SizeGroup、按钮名称与动作，以及StatusPage的既有滚动路径。先验证这一个属性；不增加外层滚动容器，不改镜像拉取/构建逻辑，不重构其他状态页。以实际子控件测量校验106px是否足够，并检查桌面横排后的布局。

补充验收覆盖360×651、366×651、651×366、366×300和1024×768：保存初始与滚到底部截图，要求两个按钮已映射且可用；操作区高度至少容纳子Box的实际最小高度；按钮完整落在操作区中；沿StatusPage既有滚动条到达底部后，按钮完整落在滚动视口与窗口中，实际高度不小于自身测得的最低高度。新增断言须先在修改前复现失败，再检查修改后的英文、中文与Wayland。

容器和卷空态采用StatusPage直接承载按钮，没有同一1px断点结构。对它们补充原滚动路径的操作可达性检查；只有实际失败才产生产品修改。先前五处合法布局调整继续保留。完成该局部修正后重新固定源码、构建两架构原生包，并使用对应ARM64 APK完成客体验收。此补充随设计存档读回成功后，才进入上述修改。

源码依据为[libadwaita 1.9.2 BreakpointBin](https://github.com/GNOME/libadwaita/blob/1.9.2/src/adw-breakpoint-bin.c)与[StatusPage模板](https://github.com/GNOME/libadwaita/blob/1.9.2/src/adw-status-page.ui)，以及当前固定源码中的 `images_panel.blp` 和原生制品截图。其余 In Scope、Out of Scope及已批准启动例外保持有效。
