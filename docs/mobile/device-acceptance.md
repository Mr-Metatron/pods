# Pixel 2 实机验收

目标是用户提供的 walleye / Wave15 r73 候选环境：aarch64 musl、Alpine 3.24 / postmarketOS、Plasma Mobile Wayland、295% 缩放、Plasma Keyboard，以及手机本机 Docker Engine。以下项目需要在 Pixel 2 上执行。完整系统 QEMU 的结果见验证报告，实机记录另存，保留日期、包版本及对应源码提交。

## 安装与环境记录

从同一次原生 aarch64 构建取得 `pods`、`pods-lang` APK 和构建者公钥，核对制品的 `SHA256SUMS`。将确认可信的公钥安装到 `/etc/apk/keys/`，再用 `apk add` 安装这两个包。APKBUILD 的构建步骤、签名与依赖见[打包说明](../../packaging/alpine/README.md)。不需要 Flatpak，程序从应用抽屉启动。

以日常桌面用户记录以下信息。保留实际输出，不用规格表替代运行状态。

```sh
uname -a
apk --no-network list --installed pods pods-lang gtk4.0 libadwaita vte3-gtk4 procps-ng
id
printf '%s\n' "$XDG_SESSION_TYPE" "$WAYLAND_DISPLAY" "$LANG"
docker version
docker info
stat -c '%U %G %a %n' /var/run/docker.sock
```

问题清单中的两行启动 schema 修复已获用户明确批准并应用；下述手机端到端项目仍需实机验证。以 `mobile` 用户启动 Pods，保留上游欢迎文案；中文会话只要求已有译文及本轮新增移动控件译文正确加载。创建本机 Docker 连接，核对连接地址与实际 socket。rootless 环境核对 `$XDG_RUNTIME_DIR/docker.sock`，已有保存连接应仍使用原地址。

## Socket 授权与失败恢复

先以无 socket 访问权的普通用户验证错误对话框：应显示实际路径及权限原因，文字可滚动阅读，关闭后仍能修改连接。不存在的路径、普通文件和停止 daemon 后的残留 socket 应得到相应错误。确认新增错误对话框可以关闭，并能返回原连接表单。重试与取消后的状态按上游原行为记录；已记录的连接取消缺陷不作为本轮修复要求。

系统 Docker 由管理员按 socket 所属组授权。通常是将 `mobile` 加入 `docker` 组，然后完整注销桌面会话并重新登录。Docker 组具有对系统 daemon 的 root 级控制权限；仅授权需要管理本机容器的用户。保持 GUI 以普通用户运行，并保持 socket 仅供获授权用户访问。

目标镜像使用 systemd 时，管理员按该镜像的服务配置启动 `docker.service`；使用 OpenRC 的 Alpine 才使用 `rc-service docker start`。远程 Docker 的进程列表还要求 daemon 所在主机安装支持 CPU 百分比字段的 `ps`，例如 Alpine 的 `procps-ng`。

## Docker 功能

先在专用测试容器上操作，测试资源采用明确前缀。覆盖创建配置、启动/停止/重启、暂停/继续、改名、删除、日志、Inspect、exec 与 resize、stats/进程、端口、bind mount 和命名卷。端口 host IP 丢失为已记录的上游问题，本轮保持原行为，不将其修复列为验收要求。

镜像操作覆盖拉取、构建、提交、标签、删除，以及测试 Registry 上的推送。拉取动作关联本地镜像的既有 ID 问题仅记录，不作为本轮修复。检查双向文件复制，记录大文件取消与失败提示的原有行为；对本轮新增的匿名临时文件检查句柄关闭后的释放。系统中有实际工作负载时，不运行全局 prune；全局清理验收只用于隔离 daemon。

自动本地 Docker smoke 测试只连接明确指定的 socket，读取版本、系统信息及列表，不创建、拉取、删除或清理用户资源。详见[本地 Docker 验证](testing-docker.md)。

## 资源与生命周期

在相同镜像、容器数量和日志速率下，分别测基线与改动版本。每组先记录系统空闲状态，再记录应用启动、连接空闲、持续输出、关闭页面后的数值。用 `pidof pods` 找到进程；`/proc/PID/status` 的 `VmRSS`、`Threads` 与 `/proc/PID/smaps_rollup` 的 `Pss` 可用于对照。

本轮不改日志窗口、导出或后台流生命周期。可以记录长时间运行时的内存表现，但已有问题只进入独立清单，不能据此扩大修复范围。检查客户端 I/O worker 数和 stats 请求并发预算；保留原统计公式与缓存行为。

使用较大的目录执行 Docker copy/build，记录输入大小、应用峰值 RSS 与缓存磁盘空间。取消路径保留上游逻辑，记录现象；仅验证新增匿名临时文件随句柄关闭释放。Docker 归档使用磁盘临时文件；Podman 镜像构建继续由上游 SDK 处理，本次没有为其声明相同内存上限。

## 图形、休眠与电量

记录默认 GTK renderer；再用以下每次启动生效的设置比较：

```sh
GDK_BACKEND=wayland GSK_RENDERER=opengl pods
```

目标规格的 GLES 由 Freedreno 提供，Vulkan 为 Lavapipe 软件路径。通过实际运行信息确认 renderer 是否使用 Adreno 540，再决定设备专用覆盖。通用 desktop 文件保留默认渲染选择。

在日志和终端打开时分别锁屏、休眠并恢复，检查界面响应、连接状态、stats、终端输入和错误重试。记录屏幕亮度、容器负载、测试时长、耗电和温度；QEMU 软件渲染的 CPU 或内存数据不能用于判断手机续航。

## 记录格式

每项写明包文件及 SHA-256、源码提交、测试环境、实际步骤、预期、实际结果、日志/截图路径。状态使用“通过”“失败”“未执行”。出现问题时保留首次错误与复现条件。直接影响手机布局、触控、导航、弹窗和输入的问题按移动适配要求作最小修复并重测。无关的上游业务问题进入独立清单；超出适配范围的功能阻塞需说明最小方案并取得用户批准。
